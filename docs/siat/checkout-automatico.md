# Checkout fiscal desde Registrar venta

La migración `20261126010000_siat_checkout_venta.sql` agrega preflight y un registro idempotente que vincula la venta comercial con la factura y la tarea fiscal existentes. El gateway comprueba certificado, CUIS, CUFD, homologación y NIT cuando corresponde antes de confirmar la venta. La RPC confirma venta, inventario y factura dentro de una transacción. Un resultado incierto se consulta con el mismo identificador; no se crea otra venta. El worker conserva la respuesta fiscal y prepara la entrega únicamente tras 908 concluyente.

La migración extiende los controles 9A solo a facturas de venta creadas por este checkout en PRUEBAS. La reversión fiscal sigue sometida a la habilitación oficial y controles existentes. No se modifican las facturas históricas.

Publicación: comprobar ambiente PRUEBAS, cola inactiva y versiones; aplicar **solo** `20261126010000_siat_checkout_venta.sql` con registro atómico en `supabase_migrations.schema_migrations`; desplegar `siat-worker` y luego `siat-gateway` con el import map existente; verificar ambas funciones y las RPC. No utilizar `supabase db push` si hay otras migraciones pendientes.

Configuración para entrega: correo requiere `RESEND_API_KEY` y `SIAT_EMAIL_FROM`; WhatsApp requiere `SIAT_WHATSAPP_ACCESS_TOKEN`, `SIAT_WHATSAPP_PHONE_NUMBER_ID`, `SIAT_WHATSAPP_TEMPLATE`, `SIAT_WHATSAPP_TEMPLATE_LANGUAGE` y una plantilla aprobada con encabezado de documento. Sin proveedor la venta puede quedar validada, pero la entrega queda pendiente y no se informa como enviada. Nunca registrar un envío manual sin evidencia. La plantilla debe estar aprobada para la cuenta y contener un encabezado DOCUMENT; usar un número internacional explícito.

Bloqueos operativos actuales: `siat_habilitado=false`, reserva offline del número 4 abierta y cero productos homologados. El checkout muestra errores concretos antes de crear la venta. La reserva se cierra solo desde Contingencias mediante la sesión administrativa del agente, cuando no existe evento ni documento pendiente; el cierre no reutiliza el número comprometido sin conciliación. La homologación exige código SIN y unidad válidos del catálogo, sin asignaciones automáticas inventadas. La habilitación general exige completar estos requisitos y volver a comprobar CUFD, certificado y permisos. No se ejecutan facturas ni mensajes al publicar.

Verificación local: `node tests/siat/checkout-postgres.mjs`, `npx vitest run tests/siat/checkout.test.tsx`, `npm run typecheck`, `npm run typecheck:agent`, `npm run build`, lint focalizado y `git diff --check`. La prueba SQL usa PostgreSQL temporal con datos sintéticos y demuestra una venta, una factura, un movimiento de inventario, reintento y concurrencia. No sustituye una emisión oficial 908 en PILOTO.
